# Infrastructure audit — 2026-09-04

**The highest-value upgrades are correctness at the model/world boundary, stronger recovery and accounting, and bounded history processing.** Broad test deletion or a rewrite would miss the most consequential problems.

Audited revision: `2d073da` (full SHA in [evidence.json](../reports/infrastructure-audit-2026-09-04/evidence.json)). The audit covers the runtime, all seven provider connectors, managed jobs, persistence, agent observations, reports, observer, and tests. It combines source inspection with offline fault injection and synthetic timing probes. No live model calls were made, and this is not a model-performance comparison.

Baseline: **493 tests passing in 8.006 seconds, one skipped**, on Python 3.12 / Ubuntu 24.04 under WSL. Source inventory: 40 top-level Python modules / 27,232 lines; 29 test modules / 11,684 lines. Size alone does not establish bloat. Retain the recent detached controller, partial-decision journal, run-scoped runtime, source-isolated cells, and event-free checkpoints.

**Evidence labels:** Reproduced = demonstrated offline; Source = implementation establishes the limitation, production impact unmeasured; Proposal = evaluate before adopting. **Priority:** P1 = fix before relying on affected paths for substantial runs; P2 = next infrastructure iteration; P3 = incremental maintenance/growth. Effort is relative, not a delivery estimate.

**Correctness and evidence integrity — upgrades 1–10.**

1. **P1 · medium — Replace failure text embedded in agent intent with typed outcomes. Reproduced.** A valid intent, “Avoid unauthorized access to stores.”, raises `ModelAuthenticationRequiredError`. Two distinct `Codex boundary failed:` messages advance the world to tick 1. An unexpected brain exception fails a sequential tick but becomes a wait in concurrent mode, advancing the same tick. The guard only catches identical whole-population ambiguous failures, and confirmed harness failures are not retryable categories. Return either a decision or an explicit transport/auth/quota/harness/model-output failure, with message text as data. Preserve the declared treatment of genuine model-output mistakes. **Acceptance:** incidental words cannot control lifecycle; infrastructure failure freezes resolution; sequential/concurrent failure semantics match. Sources: [runner.py](../agent_world/runner.py), lines 218–223, 286–331, 376–478; [metrics.py](../agent_world/metrics.py), lines 260–446.

2. **P1 · medium/large — Make world resolution transactional and validate action parameter shapes. Reproduced.** `record_agreement` with `parties: null` passes the current decision schema, then raises `TypeError`. The session saves a failed checkpoint at tick 0 containing agent 1's new memory and both response events: part of the tick has executed. Validate structural parameter types before mutation; impossible but well-formed proposals should remain ordinary engine invalid actions. Stage mutations or restore the complete pre-tick boundary, including RNG/events, on failure. **Acceptance:** fault injection after every resolution/persistence stage recovers the same world and ledger as uninterrupted execution. Sources: [world.py](../agent_world/world.py), lines 270–306, 2151–2183; [session.py](../agent_world/session.py), lines 172–450; [openrouter_brain.py](../agent_world/openrouter_brain.py), lines 32–77.

3. **P1 · small — Complete ZCode's canonical-name migration. Reproduced.** BrainSpec produces `fresh-conversation`; the shared factory passes it to ZCodeBrain, which accepts only `stateless`, so construction fails before preflight. Workspace selection also tests only legacy `stateless-v2/v3` values. Direct-constructor tests use legacy defaults and miss this integration break. Normalize aliases at entry and emit canonical metadata. This is independent of ZCode's explicitly unsupported low-effort setting. **Acceptance:** construct all providers through the real factory using canonical and historical aliases, mocking only external execution. Sources: [brain_factory.py](../agent_world/brain_factory.py), lines 57–150, 489–541; [zcode_brain.py](../agent_world/zcode_brain.py), lines 50–95, 597–610; [test_zcode_brain.py](../tests/test_zcode_brain.py).

4. **P1 · medium — Enforce real wall-clock deadlines and own subprocess lifetimes. Reproduced deadlines; source cleanup risk.** A loopback HTTP response dripping bytes succeeded after 0.478 seconds despite a 0.100-second total deadline. A child writing a partial stdout line made Codex's telemetry reader succeed after 0.363 seconds despite a 0.050-second deadline. Blocking `read(64 KiB)`/`readline()` can outlive surrounding checks. Use deadline-aware incremental reads, bounded frames, stderr draining, and one cancellation deadline across setup/attempts/retries. Manage and reap owned process groups; current launchers primarily manage immediate children. **Acceptance:** real sockets/pipes with trickle output, partial lines, noisy stderr, inherited pipes, and descendants stay bounded and leave no owned processes. Sources: [openrouter_brain.py](../agent_world/openrouter_brain.py), lines 446–565; [codex_brain.py](../agent_world/codex_brain.py), lines 801–868; [devin_brain.py](../agent_world/devin_brain.py), lines 869–1049.

5. **P1 · small/medium — Make schemas immutable and isolate run configuration. Reproduced.** Writing a four-action Codex schema followed by an eight-action schema in the shared provider workspace gives the same pathname; the first run now sees the eight-action schema. Writes are non-atomic, and CLI treatment settings flow through process environment variables. Use content-addressed schema filenames, atomic creation, and immutable execution specs passed to brains. Retain the deterministic empty working directory if it benefits caching. **Acceptance:** concurrent processes with different treatments keep independent files, settings, and request hashes. Sources: [codex_brain.py](../agent_world/codex_brain.py), lines 156–163, 956–996; [cli.py](../agent_world/cli.py), lines 791–799.

6. **P1 · medium — Make usage writes durably accountable. Reproduced.** A temporary directory used as a usage pathname makes the append fail silently; the runtime retains an in-memory row and reports no error. Reports can appear complete until restart loses that record. Decisions can be fsynced into the pending journal while corresponding usage records have only been closed. Define durability and commit receipts across usage, decisions, and checkpoints; surface persistence failure before declaring evidence durable. **Acceptance:** disk-full, permission, short-write, and crash probes cannot silently lose accounting. Sources: [usage.py](../agent_world/usage.py), lines 182–237; [brain_runtime.py](../agent_world/brain_runtime.py), lines 50–55; [runner.py](../agent_world/runner.py), lines 160–191.

7. **P1 · medium — Audit usage by identity and distinguish attempted spend from committed behavior. Reproduced coverage defect.** Two copies of agent 1's usage row, with agent 2's missing, yield 100% coverage and “clean” integrity for a two-agent tick. Coverage divides row count by response count. Give logical decisions and physical attempts stable IDs; require a one-to-one join for accepted decisions and detect duplicates/orphans. Report committed cost, discarded/retried cost, and possible unknown charges separately. Report loading currently omits partial usage ledgers; the September 2 insights entry already documents the historical spend effect. **Acceptance:** duplicate-plus-missing rows fail audit despite equal counts; attempted cost reconciles retained ledgers without double-counting cached decisions. Sources: [run_report.py](../agent_world/run_report.py), lines 147–165, 320–332, 1722–1739; [cli.py](../agent_world/cli.py), lines 866–905; [insights.md](insights.md).

8. **P1 · medium — Verify all observed model/effort identities; preserve unknowns. Reproduced.** Finalization accepts a synthetic manifest with one requested-model response and 99 unexpected-model responses as “verified,” with no blockers: it checks membership in resolved-model keys. The CLI also substitutes requested model when response identity is absent. Record requested, resolved, and provider-reported identities independently, with evidence origin and approved aliases; verify every applicable call. Do likewise for effective reasoning settings. **Acceptance:** missing identity stays unknown, unexpected identities block verification, documented backend aliases pass explicitly. Sources: [run_finalization.py](../agent_world/run_finalization.py), lines 238–292; [cli.py](../agent_world/cli.py), lines 1110–1117; [codex_brain.py](../agent_world/codex_brain.py), lines 570–587; [zcode_brain.py](../agent_world/zcode_brain.py), lines 343–389.

9. **P1 · medium — Bind checkpoints to the exact ledger prefix and publish coherent artifact generations. Reproduced ledger substitution.** Changing a valid JSON event without changing line count is accepted by checkpoint loading; rebase also checks only counts. Copied checkpoints prefer the original absolute ledger if it still exists. Store run/generation identity, committed byte offset, and verified prefix digest or equivalent integrity record. Tie event prefix, checkpoint, snapshot, and usage position to a commit marker; complete directory-sync durability where required. Retain event-free checkpoint payloads. **Acceptance:** wrong same-length ledgers are rejected, relocation is deterministic, every crash cut restores one committed generation. Sources: [persistence.py](../agent_world/persistence.py), lines 42–114; [io.py](../agent_world/io.py).

10. **P2 · medium — Bind pending decisions to the full execution specification. Reproduced at journal API.** A journal from one synthetic brain is reused with a different brain when observations match. CLI and several connector restore checks already reject model changes, mitigating ordinary managed resumes; the journal itself lacks run/model/effort/schema/source identity. Mutable schema settings are outside observation identity. Add logical decision IDs/spec digests; share validation between usage reconciliation and journal loading; enforce read-size as well as write-size limits. **Acceptance:** exact resumes reuse decisions; changed execution inputs invalidate or reject caches before accounting changes. Sources: [runner.py](../agent_world/runner.py), lines 40–155, 199–215; [cli.py](../agent_world/cli.py), lines 860–895.

**Operations and connector capability — upgrades 11–20.**

11. **P2 · medium — Persist quota state and use explicit controller leases. Source.** Wait budget/backoff live in session memory; reset timing is reconstructed from event-file mtime. A live process whose last control event is quota-wait is exempt from stall reaping even beyond the expected reset. Sleep blocks the normal stop hook. Persist absolute resume deadline, consumed budget, and lease expiry; wait interruptibly. Test stop latency, budget continuity across crashes, and overdue waits while preserving the frozen tick. Sources: [session.py](../agent_world/session.py), lines 135–140, 466–538; [run_controller.py](../agent_world/run_controller.py), lines 121–145, 364–403.

12. **P2 · medium — Freeze the complete execution environment and clarify fingerprint scope. Source.** Cells pin source, but controllers run from mutable source_root; executable discovery can select newer installed CLIs. Core benchmark fingerprint inputs omit construction/persistence helpers such as brain_factory.py and persistence.py. Reused cohort worktrees check HEAD, not dirty contents. Record binary version/digest, non-secret effective settings, source dependencies, and separate simulation/connector/scorer versions. Pin controller/finalizer code or declare a reviewed migration. Distinguish infrastructure compatibility from treatment changes. Sources: [managed_runs.py](../agent_world/managed_runs.py), lines 440–508; [benchmarks.py](../agent_world/benchmarks.py), lines 339–383; [run-isolated-cohort](../scripts/run-isolated-cohort); connector executable resolvers.

13. **P2 · medium — Schedule provider-ready work before consuming global workers. Reproduced lock coupling; source scheduling risk.** Provider semaphores are acquired inside executor workers, so one provider's queued tasks can occupy workers another provider could use. Throttle sleeps holding the shared runtime lock: an unrelated provider lookup blocked for 0.270 seconds in the probe. Jobs independently enforce ceilings against shared account quotas. Sleep outside shared locks, admit provider-ready work before dispatch, and optionally share account admission across jobs. Measure queue time/starvation without changing tick resolution order. Sources: [runner.py](../agent_world/runner.py), lines 423–478; [brain_runtime.py](../agent_world/brain_runtime.py), lines 176–186.

14. **P2 · medium — Make managed-launch identity and crash ownership unambiguous. Reproduced collision; source crash gaps.** Valid IDs audit.x and audit-x produce the same tmux name; truncation adds collisions. Failure in a later cell can leave earlier cells running before controller creation. Job persistence follows spawning, leaving a crash gap. Hash full job/cell identity, persist launch intent before spawning, and reconcile deterministic ownership after restart. Test failure after each stage: every live child needs exactly one recorded owner/recovery path. Source: [managed_runs.py](../agent_world/managed_runs.py), lines 308–310, 373–398, 546–571.

15. **P2 · medium — Route model-backed observer launches through managed jobs. Source.** The UI starts a daemon thread in its own process, uses fixed output paths, and lacks managed source isolation/detached supervision. Closing the observer process ends that run. Make the UI a managed-job client with durable selection, controls, and unique artifacts. A lightweight explicit in-process route can remain for free diagnostics. Test observer restarts during running/paused jobs. Source: [observer.py](../agent_world/observer.py), lines 103–137, 163–251.

16. **P2 · medium — Make finalization independently supervised, idempotent, and atomic. Source.** Controller finalization is synchronous, including a possible 900-second v6 judge, delaying supervision. Reports are directly overwritten. Rebuilding reports omits the plan-usage argument, potentially removing previously reported plan telemetry. A failed automatic attempt records the completed-seed signature as last attempted, preventing same-signature automatic retry. Use an independently supervised finalizer with transaction identity, preserve all report inputs, and atomically publish reports/readiness. Distinguish retryable report errors from one-shot judge attempts that must not be automatically repeated. Sources: [run_controller.py](../agent_world/run_controller.py), lines 440–485; [run_finalization.py](../agent_world/run_finalization.py), lines 350–374; [run_report.py](../agent_world/run_report.py), lines 1654–1680.

17. **P2 · medium — Share a typed configuration/capability registry. Reproduced validation mismatch; source duplication.** JSON config, argparse, observer parsing, BrainSpec, and constructors duplicate validation. runtime.ticks=true passes JSON validation; many settings are validated only in the launched child. Centralize finite numeric types, mode/effort/schema support, population parsing, and alias normalization; derive UI choices and docs. Dry-run should catch invalid settings before creating artifacts/worktrees. Sources: [managed_runs.py](../agent_world/managed_runs.py), lines 92–212; [brain_factory.py](../agent_world/brain_factory.py), lines 57–150; [observer.py](../agent_world/observer.py), lines 259–396; [cli.py](../agent_world/cli.py).

18. **P2 · medium/large — Extract the shared connector pipeline. Source.** Adapters repeat prompt preparation, retries, attribution, usage, conversation resets, and subprocess logic; several decide methods exceed 300 lines. Compose shared preparation, execution, typed validation, and telemetry, leaving provider flags/parsers small and explicit. Migrate one provider at a time against contract fixtures. Avoid an inheritance hierarchy that hides provider differences. Sources: all seven *_brain.py modules and [brain_factory.py](../agent_world/brain_factory.py).

19. **P2 · medium — Verify effective tool isolation and capability parity. Source; no demonstrated tool escape.** Claude removes tools, Codex disables features, Cursor uses Ask/sandbox, Devin rejects client requests, and Grok/ZCode use different fences. ZCode's deny list names eight tools while documentation claims broader delegation/skill isolation. Maintain versioned capabilities and inspect actual tool events in acceptance tests; prefer empty allowlists where supported. New vendor tools/settings must not silently change the boundary. Sources: [claude_brain.py](../agent_world/claude_brain.py), lines 504–544; [cursor_brain.py](../agent_world/cursor_brain.py), lines 487–510; [devin_brain.py](../agent_world/devin_brain.py), lines 990–1025; [zcode_brain.py](../agent_world/zcode_brain.py), lines 40–44; [agent-boundaries.md](agent-boundaries.md).

20. **P2 · medium/large — Evaluate warm harness processes with fresh conversations. Proposal.** Each decision launches a CLI; Devin initializes ACP and configures sessions each turn. Existing persistent-conversation mode changes agent memory and is not an equivalent speed switch. Measure process/auth/setup time first. Where supported, pool transports while creating isolated conversations per decision; verify prompt/tool equivalence and record a connector version. No speedup or token saving is established yet. **Cost, scaling, and maintainability — upgrades 21–30.**

21. **P2 · medium — Bound historical observations with a versioned information policy. Reproduced.** Organic observations include every contract, including completed ones; group rules/agreements can also grow. Adding 1,000 fulfilled contracts grew dynamic JSON from 1,415 to 229,325 characters. ZCode/Grok pass prompts as command arguments, adding an eventual OS argument-size ceiling. Provide active obligations plus defined recent/summary views or explicit retrieval; record component sizes and truncation. Version and evaluate changed information, rather than silently changing an existing benchmark. Sources: [interface.py](../agent_world/interface.py), lines 86–98, 245–281; [models.py](../agent_world/models.py), contract/group summaries.

22. **P2 · small/medium — Prepare static prompts once and serialize each decision once. Source plus sizes.** Brains and runner logging rebuild static context, dynamic JSON, and hashes independently. Initial organic static context measured 7,678 characters versus 1,415 dynamic—not token/billing measurements. OpenRouter hashes compact sorted bytes but sends a separately serialized payload. Use immutable prepared prompts keyed by config/rules/schema digests and pass exact bytes/hashes to transport/logging. Verify byte equivalence; measure provider cache hits before claiming monetary savings. Sources: [runner.py](../agent_world/runner.py), lines 480–539; [openrouter_brain.py](../agent_world/openrouter_brain.py), lines 185–197, 481–487; other connector decide methods.

23. **P2 · medium/large — Index recent events and incrementally aggregate history. Measured scaling.** Organic observations scan all events for ledger notes; agents with few invalid actions scan history for feedback. Full events/usage remain in memory and metrics rescan them. Observation construction rose from 0.106 ms to 5.872 ms with 100,000 synthetic events. Maintain per-agent feedback, ledger tails/counts, spatial agent indexes, and incremental counters while preserving the durable ledger. Differentially verify identical observations/metrics and retain historical replay/query access. Sources: [interface.py](../agent_world/interface.py), lines 144–153, 928–953; [metrics.py](../agent_world/metrics.py); [brain_runtime.py](../agent_world/brain_runtime.py).

24. **P2 · medium — Serve observer/status incrementally and align historical views with committed ticks. Measured plus source.** Observer reparses the whole log every request; the UI polls every 1.5 seconds. At 100,000 synthetic events, a request took 542 ms median. A controller scan took 240 ms in a worst-case history without recent control events; even with recent controls it reads the whole file. SnapshotHistory stops admitting ticks at its cap, samples rather than captures every tick, and uses <= tick for events although completed snapshot N precedes decision events labeled N. Tail by byte offset, cache summaries, use cursors/ETags or push, and reject stale responses. Capture/reconstruct committed snapshots with explicit ring/archive retention. Sources: [observer.py](../agent_world/observer.py), lines 469–508, 623–656; [run_controller.py](../agent_world/run_controller.py), lines 95–108; [observer.html](../agent_world/static/observer.html).

25. **P2 · medium — Add phase-level telemetry and resource budgets. Source/proposal.** Request durations mix setup/provider/retry time and exclude much queue/throttle/persistence work. Config has ticks/workers/quota wait but no aggregate token/spend/attempt/output-size budget. ACP queues/transcripts and several response readers are unbounded. Measure queue, prompt, setup, first-byte, completion, parse, journal, checkpoint, and report phases with monotonic clocks. Enforce configurable budgets at safe boundaries and preserve unknown cost/token values. Validate stop reasons and memory/output bounds. Sources: [provider_telemetry.py](../agent_world/provider_telemetry.py); [runner.py](../agent_world/runner.py); [managed_runs.py](../agent_world/managed_runs.py); [devin_brain.py](../agent_world/devin_brain.py), lines 891–909.

**Measured limits and what to keep.**

These are local synthetic timings, not production latency estimates. They isolate growth/I/O behavior and do not establish that Python CPU dominates model-backed runs. Snapshot creation stayed around 0.43 ms with 100,000 added historical events, because those events are excluded. The existing checkpoint-size test also protects event-free checkpoints. Preserve both.

The eight-second suite does not justify mass test deletion. Source footprint alone does not justify a new language, database service, or distributed queue. SQLite generation already uses a temporary database and atomic replacement. Stable prompt prefixes, explicit conversation boundaries, source-isolated cells, and reuse of successful partial-tick decisions should remain.

**Suggested implementation order.**

- Add regression coverage and fix direct behavior risks: 1–5.
- Make evidence trustworthy, then close lifecycle gaps: 6–16.
- Consolidate capabilities/connectors and measure representative workloads: 17–20, 25–27.
- Bound information/history growth and optimize projections: 21–24. Agent-visible information changes need a versioned treatment.
- Continue scoped maintenance/export improvements: 28–30.
